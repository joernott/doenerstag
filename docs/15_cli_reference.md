# 15 Command line reference

Every verb, every subcommand and every flag, as the binary itself reports them.

Generated by `scripts/clidocs.sh` from the command tree. Do not edit by hand:
run the script instead, which CI checks. What the flags *mean*, and the
reasoning behind the ones whose behaviour is not obvious from a line of help
text, is in [09_configuration.md](09_configuration.md).

Three rules hold across the whole tree and are not repeated per command:

- **A secret is never accepted on the command line.** `--database-password`,
  `--database-root-password`, `--database-admin-password`, `--root-password`,
  `--jwt-secret` and `--mail-password` are read from the configuration file, the
  environment or an interactive prompt. Passing one as an argument is a fatal
  error, because command lines are visible in the process list and end up in
  shell history.
- **Every verb inherits the global flags**, so `-c` names the configuration file
  and `-L` the log destination everywhere.
- **A verb that needs a subcommand and is given none prints its help and exits
  non-zero**, so a script notices.

## doenerstag

```
doenerstag coordinates food orders for a group.

One person opens an order for a restaurant and a pickup time, everyone else
adds what they want, and a summary page says what to order and who owes what.

It does not take payments and does not place orders with restaurants.

Usage:
  doenerstag [flags]
  doenerstag [command]

Available Commands:
  cleanup     Remove expired orders and unreferenced data
  completion  Generate the autocompletion script for the specified shell
  help        Help about any command
  install     Set up the database and write a configuration file
  order       Inspect and remove orders
  restaurant  Manage restaurants from the command line
  server      Run the web server
  update      Update an existing installation
  user        Manage user accounts
  version     Show the installed application and schema version

Flags:
      --base-url string           public address of this installation, for links in mail, e.g. https://doener.example
  -c, --config string             path to the configuration file (default "doenerstag.yaml")
  -N, --database-name string      database name (default "doenerstag")
  -P, --database-port int         PostgreSQL port (default 5432)
  -S, --database-server string    PostgreSQL host name (default "localhost")
      --database-sslmode string   TLS mode for the database connection: disable, allow, prefer, require, verify-ca or verify-full (default "prefer")
  -U, --database-user string      database user used at runtime (default "doener")
  -h, --help                      help for doenerstag
  -L, --log-file string           log destination; empty writes to stdout
  -l, --log-level string          log level: FATAL, ERROR, WARN, INFO or DEBUG (default "INFO")
      --max-connection-pool int   upper bound for open and for idle database connections (default 10)
  -v, --version                   version for doenerstag

Use "doenerstag [command] --help" for more information about a command.
```
